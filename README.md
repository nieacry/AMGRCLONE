# AMG rclone UI

Настільний клієнт Dropbox для кількох облікових записів. Шрифти збільшено; зайві заголовки та повтори версії прибрано. Український інтерфейс за замовчуванням; **УКР / EN** праворуч угорі зберігає вибір. Використовується наданий логотип Animagrad.

## Переносимий ZIP

Для співробітників передається один ZIP: розпакувати всю папку й запустити зовнішній EXE. Electron, rclone та Cloud Files provider включені; окремі Node.js, Visual C++ Runtime або Dropbox Desktop не потрібні. Потрібна підтримувана Windows x64 із системним Cloud Files API та NTFS-папка синхронізації. Інструкції першого запуску українською та англійською лежать у release/START-HERE.*.md. Збірка перевіряє імпорти всіх EXE/DLL і відхиляє відсутні сторонні runtimes; звіт — release/portability.json.

0.15.4 виправляє 0x80070186 для пересозданої папки зі старим записом Провідника. Власна застаріла реєстрація очищується тільки за відсутності Cloud Files kernel root і локальних файлів; чужі активні корені не перепризначаються. Після Shell реєстрації повторно встановлюється й перевіряється CfAPI kernel root. Порожнє невдало підключене сховище можна безпечно відключити/reset без успішного init або звернення до Dropbox. Невідомі залишки кешу блокують reset, щоб зберегти можливі єдині копії даних.

## Облікові записи Dropbox

Тип входу визначається через Dropbox API. Business використовує власний бізнес-корінь, особистий акаунт — власний особистий корінь. Дерево завантажує тільки дочірні елементи поточної папки з підтримкою сторінок і тих самих namespace, що й нативна синхронізація. Якщо визначити корінь неможливо, програма показує помилку замість порожнього списку.

## Фактична доступність файлів

У нативному режимі список розрізняє **Лише онлайн**, **Завантажено в кеш** і **Закріплено локально**. Відкриття файла у Провіднику оновлює фактичний стан без зміни успадкованого правила. Стан і правило мають окремі стовпці, рядки займають 36 px замість 54 px; кеш не дорівнює постійному закріпленню. Для папки з різною доступністю дочірніх файлів показано **Частково завантажено**, для поточних передач — синій стан синхронізації. Невідомі дані та конфлікти не видаються за завантажені файли.

Видимі файли перевіряються через читання атрибутів Windows, без відкриття їхнього вмісту й без завантаження. Показання працюють і при паузі фонової синхронізації. Кеш зберігається після перезапуску; закріплення й звільнення місця залишаються окремими діями.

## Оновлення та профіль

Дані користувача зберігаються в **Документи\AMGRCLONE** окремо від папки програми. Перший запуск переносить старий профіль `%APPDATA%\cloudlane`, не перезаписуючи наявний новий профіль. Зашифровані входи, правила, журнал, власні subst-диски, ідентичності плейсхолдерів і незавершені операції зберігаються. Старий профіль залишається резервною копією; службові шляхи bisync переводяться на нове розташування.

Для користувачів є готовий `versions/AMG-rclone-UI-0.15.4-win-x64.zip` та SHA-256. Перед оновленням дочекайтеся передачі файлів і виберіть **Вийти** у треї або **Налаштування → Вийти для оновлення**. Розпакуйте ZIP окремо, замініть всю папку програми зі збереженням її шляху та запустіть зовнішній EXE. Профіль і локальні папки Dropbox не видаляйте; reset для оновлення не потрібен. Детальні інструкції: [українською](docs/UPDATING.uk.md), [англійською](docs/UPDATING.en.md); вони також включені до `release/` готової програми.

Перед зміною версії створюється знімок профілю в `Документи\AMGRCLONE\profile-backups`, включно з консистентною SQLite-копією. Міграції схеми виконуються транзакційно; невідомий новіший формат блокує запуск до зміни даних. Знімок профілю не замінює резервну копію файлів Dropbox. Автоматичного завантаження нових випусків ще немає.

Картка локальної папки показується лише в **Усі файли**. Біля папки, з якої створено диск, відображається його буква і стан. Зайвий підпис над меню прибрано.

## Журнал файлів і видалення

Меню: **Усі файли → Журнал → Диски Dropbox → Правила синхронізації**. Журнал зберігає час, шлях, розмір, дію й результат операції для кожного акаунта: фактичні завантаження, надсилання, перейменування, видалення, доступність online-only та помилки. Є пошук, фільтр результату й наступні сторінки; список прокручується всередині відведеної області, пошук і заголовки залишаються нерухомими. Історія починає накопичуватися з цього випуску; минулі події не вигадуються. Повний reset очищує журнал. Наявний журнал сеансів bisync теж збережено.

Виправлено 0x80070185 під час відправлення файла до кошика: попередні delete/undelete перевірки Windows не видаляють дані в Dropbox. Провайдер спочатку зберігає намір, чекає завершення локального видалення/переміщення й потім видаляє відповідний Dropbox ID із перевіркою revision. При помилці мережі намір залишається для повтору, зокрема після перезапуску. Повторна дія не відправляє осиротілий локальний файл назад у Dropbox. Локальні плейсхолдери, залишені старою помилкою, зберігаються; завантажений файл можна повторно видалити звичайною дією у Провіднику. Windows може видаляти online-only файл без локальної копії в кошику; серверне видалення не є permanent-delete API. Переміщення в довільну папку за межами sync root поки не підтримується.

## Запуск і версії

Актуальна самодостатня Windows-збірка: `publish/AMG rclone UI.exe`. Можна також запустити `Запустити AMG rclone UI.cmd`: він відкриє publish, а за відсутності збірки — вихідний проєкт через npm. Node.js для готової збірки не потрібен; rclone і Cloud Files helper включені.

Архів незмінних випусків: `versions/<версія>/` — локально, поза git; ті самі ZIP публікуються в GitHub Releases. Кожна версія містить програму, `release/source.zip` без облікових даних і `release/version.json` з SHA-256. Нумерація: 0.15.4 → 0.15.5 … 0.15.9 → 0.16.0. Робоча папка: `D:\AnimagradRnD\DEV\AMG rclone UI`.

## Структура готової збірки

```text
publish/
  AMG rclone UI.exe
  app/
  release/
```

У корені залишено тільки launcher EXE. У `app/` розташована вся Electron-програма, DLL, ресурси, rclone і native helper; у `release/` — вихідні файли, контрольні суми та інструкції оновлення. Для перенесення програми копіюйте всю папку publish. Launcher знаходить app відносно власного шляху, підтримує пробіли/Unicode, передає аргументи без shell і не створює службових файлів поруч із собою. Автозапуск використовує зовнішній EXE. Профіль залишається в Документах.

## Диски з локальних підпапок — Windows

У дереві папок натисніть значок диска біля потрібної папки або скористайтеся розділом **Диски Dropbox**. Оберіть наявну локальну підпапку й вільну букву A–Z. Наприклад, `D:\dbproject\Project1` можна показати як `P:`.

Викликається саме системний `subst.exe`, без командної оболонки. Корінь, абсолютна ієрархія, правила та шляхи синхронізації не змінюються. Це працює і зі звичайною локальною копією, і з папкою нативного провайдера. Папка має вже існувати локально.

Застосунок зберігає власний список прив’язок: випадковий ID, обліковий запис, букву, незмінний абсолютний корінь і відносну папку. **Відключити** приймає лише ID зі списку. Перед `subst /D` повторно перевіряється точна поточна ціль. Системні диски, сторонні прив’язки й букви з іншим шляхом не видаляються. Файли та оригінальні папки не видаляються. Для видалення облікового запису спочатку відключіть його власні диски.

Вихід із програми не знімає subst-прив’язки в поточному сеансі Windows. Після перезавантаження програма відновлює свій список під час запуску, тільки якщо буква вільна або вже веде до того самого шляху. Зайнята чужим диском буква не перехоплюється. Для відновлення після входу в Windows увімкніть автозапуск. Дані online-only потребують працюючого провайдера для завантаження.

## Трей та запуск

У налаштуваннях: **Запускати після входу в систему**, **Запускати одразу в треї**. Обидві опції вимкнено за замовчуванням. Хрестик приховує вікно; пункт **Вийти** в треї завершує програму. Натискання на значок повертає вікно.

Значок анімується під час передавання, зелений після успішної перевірки, жовтий за наявності змін, червоний при помилці; пауза й початковий стан відрізняються. Зелений означає останній відомий результат із часом перевірки, а не безперервну гарантію стану Dropbox.

## Нативні online-only файли — Windows, рання реалізація

У Windows вибір порожньої локальної папки NTFS автоматично вмикає нативний провайдер. Усі папки поточного простору Dropbox одразу обрані як «Лише онлайн»: завантажуються метадані. Окремого перемикача та панелі провайдера немає. Непорожня чи непідтримувана папка отримує відмову; наявні файли не очищаються й не переносяться автоматично. Один обліковий запис використовує один двигун: у нативному режимі bisync для нього вимкнено.

У нижньому рядку показано загальний статус і час останньої повністю успішної синхронізації обраного акаунта. Час зберігається між запусками; невдала або неповна перевірка його не оновлює. Помилка відображається окремо з назвою акаунта й шляхом операції. Тимчасова блокування файла (0x80070322/0x80070020/0x80070021) очікує автоматичної повторної спроби, а не видається за конфлікт даних.

Вибрані гілки створюються як справжні Cloud Files placeholders. Папки й файли підтримують успадковані або окремі режими **Лише онлайн** / **На комп’ютері**. Читання через Провідник чи іншу програму завантажує потрібні діапазони. Локальний режим закріплює та повністю завантажує файл. Повернення до online-only звільняє тільки чисті підтверджені дані; незбережені зміни не відкидаються. Перегляд прев’ю або індексація також можуть ініціювати читання.

Зміни локальних файлів перевіряються кожні 5 секунд, Dropbox — раз на 60 секунд або кнопкою оновлення. Завантаження прив’язане до незмінної серверної revision; відправлення перевіряє попередню revision і Dropbox content hash. Підтримано створення, зміни, перейменування, видалення та повторне підключення після запуску. Конфлікт зберігає локальні дані й зупиняє автоматичну заміну; повноцінного вікна вирішення конфліктів ще немає.

Для початкової реєстрації потрібен порожній окремий NTFS-корінь без вкладення в інший sync root. Звичайний bisync відмовляється працювати з OS-зареєстрованим хмарним коренем. Відключення облікового запису підтримується: кнопка доступна в налаштуваннях, а перед виходом власні плейсхолдери завантажуються і перетворюються на звичайні локальні файли. Відключаються лише власні subst-прив’язки цього акаунта; інші акаунти не змінюються. Повний скидання застосунку може безпечно згорнути власні нативні корені зі збереженням локальних даних; автоматична міграція наявної непорожньої звичайної копії ще не реалізована.

Це рання Windows-реалізація. Системне читання, pin/unpin, dirty-захист, зміни, конфлікти й рестарт перевірені на реальному Windows Cloud Files API з локальним тестовим транспортом. Dropbox HTTP-контракти перевірені ізольованими тестами; новий нативний транспорт ще не випробувано наскрізно на справжньому Dropbox. Word/Adobe atomic-save, великі бібліотеки, нестабільна мережа та тривалий offline потребують окремих випробувань. macOS File Provider поки не реалізовано; macOS-збірку цього випуску не створено.

## Службові файли та Проводник

Нативний режим не створює `.amg-access-*`. Після успішного переходу або старту вже нативного облікового запису старі пари bisync отримують стан retired. Програма прибирає тільки маркери, що записані в історії цього підключення: точне ім’я, розмір і вміст мають збігатися. Dropbox-видалення прив’язане до ID та перевіреної revision. Чужі маркери та змінені файли залишаються. Квитанції зберігаються локально в SQLite; невдалі спроби можна повторити кнопкою очистки в налаштуваннях. Старі копії та резервні папки не видаляються. Активні звичайні пари зберігають перевірку доступу й не очищаються до переходу на нативний режим.

Корені реєструються в Windows Shell через StorageProviderSyncRootManager. Проводник показує стандартні системні стани: хмаринка для online-only, зелена позначка для локальних файлів і сині стрілки для змін, що синхронізуються або очікують передавання. Розташування значка залежить від виду Проводника: біля імені у великих значках, у колонці стану в табличному вигляді. Реєстрація та зміни станів супроводжуються системними повідомленнями оновлення. Довільне розташування власного overlay поверх іконки не нав’язується.

## Видалена локальна папка та вихід

Якщо корінь видалили або перемістили вручну, показується конкретне повідомлення про відсутню папку. Вихід і reset не намагаються підключити неіснуючий корінь і не створюють порожню заміну. Каталог цього акаунта та залишок native-cache спочатку зберігаються в `userData/recovery/<account-id>-<uuid>/` без OAuth-токенів; лише потім очищається збережений вхід. Каталог recovery не видаляється під час reset, бо може містити єдині копії незавершених локальних правок. Автоматичний імпорт цих даних ще не реалізований.

Недоступні або невідомі реєстрації sync root не від’єднуються примусово. Якщо папку перемістили, краще повернути її за попереднім шляхом перед виходом, щоб програма могла завантажити та зберегти повні локальні копії. Вихід не надсилає операцій видалення користувацьких файлів до Dropbox. Це не відновлює файли, які раніше видалили вручну.

## Повне скидання для тестування

У налаштуваннях є **Скинути застосунок** з окремим підтвердженням. Воно очищає збережені входи, налаштування, правила, журнал, локальну службову базу, cookies, localStorage і кеш застосунку; вимикає автозапуск та відключає тільки власні subst-прив’язки. Зовнішній браузер має власний сеанс Dropbox і тут не очищається.

До видалення входів усі власні online-only файли завантажуються. Лише після успіху вони перетворюються на звичайні файли, а корінь відключається від Cloud Files/Shell. Незавантажені чи сторонні placeholders не видаляються. Незавершені локальні правки зберігаються у файлах без примусового upload. Якщо ревізія недоступна, немає мережі, місця або файл заблоковано, скидання зупиняється, входи й каталог зберігаються для повторної спроби. Частково відключені корені залишаються звичайними локальними копіями. Поки скидання не завершене, фонова синхронізація цих коренів призупинена.

## Синхронізація

1. Підключіть Dropbox у браузері або використайте вже збережений вхід.
2. Простір обирається автоматично за входом: Business показує бізнес-папки цього акаунта, особистий вхід — особисті папки цього акаунта. Дані різних входів не об’єднуються. Ручного перемикача просторів немає. Помилково підключений старою версією порожній нативний корінь виправляється зі збереженням локального шляху; за наявності файлів, історії пар або дисків автоматичний перехід зупиняється.
3. Оберіть звичайну локальну папку поза Dropbox/OneDrive та іншими системними провайдерами. Різні облікові записи не можуть мати вкладені чи однакові локальні корені.
4. Позначте потрібну папку й задайте **На комп’ютері** у правій панелі. Дочірні елементи успадковують режим; чекбокс папки змінює вибір усього піддерева, зберігаючи режими окремих файлів.
5. Для початкового об’єднання оберіть пріоритет Dropbox або локальної версії. Файли, що існують лише з одного боку, копіюються на інший. Різні версії за однаковим шляхом замінюються обраною стороною з резервною копією попередньої версії.
6. Натисніть **Перевірити план**. Потрібні локальні підпапки створюються автоматично. Сам перегляд не передає файлів у Dropbox.
7. Перегляньте папки, пріоритет, відкладені правила та журнал; підтвердьте зміни й натисніть **Почати синхронізацію**.
8. Після першого успішного запуску наступні виконуються як звичайний bisync: зміни й видалення поширюються в обидва боки, конфліктні версії зберігаються окремо.

План чинний 10 хвилин і прив’язаний до облікового запису, простору, правил, покоління історії та знімків метаданих обох сторін. Зміни після перегляду потребують нової перевірки. Знімки використовують шляхи, розміри й час зміни; це не атомарне блокування файлів від редагування зовнішніми програмами.

**Захист видалень — 10% за запуск.** Якщо rclone блокує масове видалення, застосунок не додає `--force`. Для маленької папки навіть видалення одного файла може перевищити поріг. Повторна звірка об’єднує дані заново і не є способом підтвердження масового видалення.

## Резервування та відновлення

- Заміни й видалення зберігаються в `.amg-backups/<account>/<pair>/<run>` у Dropbox та в `.amg-backups/<pair>/<run>` під локальним коренем.
- У командному просторі оберіть підпапку всередині командної папки: хмарні резервні копії розміщуються в її командній папці поруч із синхронізованою гілкою. Синхронізація цілого командного кореня наразі відкладається.
- Для кожної пари створюються службові файли `.amg-access-*` з однаковим вмістом на обох сторонах. Зникнення або зміна маркера зупиняє звичайний запуск.
- SQLite зберігає пари, каталог відомих ID, покоління історії та журнал. Стан bisync має окремий сталий workdir на пару. Попередня перевірка використовує копію стану, не змінюючи робочої історії.
- Помилка або переривання реального запуску переводить пару в **Потрібна звірка**. Жодного автоматичного `--resync` немає. Після перевірки даних користувач окремо запитує повторну звірку, переглядає новий план і підтверджує його.
- Повторна звірка використовує новий каталог стану, а не видаляє старий lock-файл. Історія й попередні резервні копії залишаються.
- Вкладка **Журнал** показує результати й розташування копій. Відновлення файла зараз виконується вручну з відповідної резервної папки; автоматична кнопка відновлення ще не реалізована. У Dropbox резервні копії доступні через вебінтерфейс або інший клієнт.

Резервні копії поки не очищаються автоматично і займають місце з обох боків.

Порівняння використовує розмір, час і контрольні суми; різниця часу до секунди допускається з перевіркою вмісту. Це обережний режим: читання контрольних сум великих локальних файлів може займати значний час. Оптимізація каталогу хешів — наступний крок.

## Розклад

У **Правилах синхронізації** є ручний режим та інтервали 5, 15, 30 і 60 хвилин. Розклад дозволений після успішної ручної синхронізації всіх обраних локальних папок. Він працює, поки застосунок відкритий. Кожен запуск повторно перевіряє стан; початкове об’єднання за розкладом заборонено. Помилка ставить розклад на паузу; зміна правил вимикає його. Є кнопки паузи та відновлення.

## Дані та розробка

Вихідний код ведеться в git; CI (GitHub Actions, Windows) запускає `tsc --noEmit` і `npm test` на кожен коміт. Назва продукту для користувача — **AMG rclone UI**. Внутрішній ідентифікатор `cloudlane` (назва пакета, `appId`, старий профіль `%APPDATA%\cloudlane`) навмисно не змінюється: від нього залежать блокування єдиного екземпляра, реєстрація в Провіднику та міграція профілю.

Профіль 0.15.0 розташований у системній папці Документи/AMGRCLONE; `vault.bin` шифрується Electron safeStorage (DPAPI/Keychain). SQLite зберігає метадані, каталог нативних файлів та журнал без токенів. Токени не передаються UI, аргументам команд чи журналу. Для rclone створюється тимчасовий приватний config, що очищається після команди й після аварії під час наступного старту. Процеси поточного користувача не ізольовані від цих секретів повністю.

Для вихідного проєкту потрібні Node.js 24+, `npm ci`, Electron і rclone 1.70+. `scripts/fetch-rclone.ps1` завантажує Windows rclone з перевіркою SHA-256. Helper компілюється MSVC 2022 і Windows SDK 10.0.26100.0. Підпис інсталятора й автоматичне оновлення ще не налаштовані.

```text
npm run build:native
npm run build
npm test
npm run test:native
npm run test:subst
npm run test:ui
node scripts/onboarding-smoke.mjs
node scripts/logout-smoke.mjs
npm run release:stage
npm run test:packaged
node scripts/onboarding-smoke.mjs --packaged
node scripts/logout-smoke.mjs --packaged
npm run release:publish
```

`release:stage` готує збірку; `release:publish` перевіряє її хеші, створює незмінний архів і оновлює publish. Повторний випуск тієї самої версії заборонено. `npm run version:next` показує наступний номер. Браузерний макет `npm run dev` використовує лише вигадані дані з позначкою демо.

Тести використовують випадкові папки `.runtime/` і не підключають користувацький Dropbox, не змінюють його автозапуск і не відключають сторонні диски.

- `core/drives.mjs`, `core/subst-drives.mjs` — власний реєстр дисків і subst.
- `native/windows/CloudHost.cpp` — системні placeholders, діапазони й перевірки власності.
- `core/native-provider.mjs`, `core/dropbox-transport.mjs` — нативна синхронізація та revision-aware Dropbox API.
- `core/sync-engine.mjs`, `core/store.mjs` — звичайний bisync, SQLite, історія й резервування.
- `electron/` — захищені входи, IPC, трей, запуск і планувальник.
- `src/`, `core/i18n.mjs` — UI, логотип і українські/англійські тексти.
- `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/verification/` — архітектура, наступні кроки й звіти перевірок.
