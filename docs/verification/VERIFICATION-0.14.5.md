# Перевірка 0.14.5

Відтворено реальний SHFileOperation/Recycle Bin сценарій 0.14.4: NOTIFY_DELETE(flags=0) → NOTIFY_DELETE(flags=IS_UNDELETE) → NOTIFY_RENAME(out of scope у $Recycle.Bin). Стара версія видаляла серверну копію й catalog уже на першому кроці та відхиляла move до кошика, залишаючи локальний placeholder.

Тепер delete callbacks лише перевіряють файл і зберігають durable intent у SQLite; undelete скасовує проміжний намір. Дозволяється лише точний кошик поточного Windows SID на цьому томі, довільні out-of-scope targets залишаються заблоковані. Перед видаленням з Dropbox повторно перевіряється відсутність вихідного placeholder. Permanent-delete intents мають settle interval проти проміжних Windows перевірок. Remote delete revision-aware, повторне not_found безпечне; нові/змінені remote діти папки блокують його. Каталог і success log завершуються однією транзакцією. Невдала мережна операція переживає перезапуск. Root startup не втрачає timer retry через помилку відкладеного delete.

Загублений старою версією catalog відновлюється лише при збігу placeholder identity з remote revision/ID. Відсутні на сервері локальні placeholders позначаються orphaned, зберігаються й не завантажуються назад автоматично. Явне повторне видалення повністю завантаженої orphaned копії проходить без відправлення. Незбережені зміни та невідомі revisions не відкидаються. Тестові roots від'єднано зі збереженням їхніх bytes; user drop01 не очищався й не видалявся.

Schema 5 додає durable native_deletions і file_events. Вузький read-only IPC має перевірку акаунта, фільтрів і курсора; SQL параметризований. Журнал містить UTC time, шлях, kind, дію, напрям, розмір, результат і безпечний код помилки; локалізований час має секунди. Не записуються tokens/OAuth/config, статистика не видається за передачу, dry-run не створює file transfers. Явно відрізняються metadata placeholder та завантаження байтів. Розділ має пошук, error filter, cursor pagination і внутрішню прокрутку з фіксованими заголовками. Порядок меню: Files, Activity, Dropbox drives, Sync rules.

Пройдено 55 unit/integration tests; реальні native hydration/pin/dehydrate/rename/delete/conflict/reconnect smoke; Windows recycle smoke для pinned, online-only та вкладеної папки, permanent-delete, старої orphan копії й мережної помилки з restart; journal smoke для actual local-only upload/download, persistence, UK/EN, menu order, literal search, errors, account isolation, 100/200 cursor rows і reset; загальний source UI smoke з real rclone sync. Пройдено також packaged journal/recycle/desktop/onboarding/logout/launcher smoke: внутрішня прокрутка й нерухомі заголовки на 200 записах, справжні native видалення файлів/папки, orphan, offline startup retry, restart, власні subst, tray/minimized, reset/cookies і missing-root recovery. Бінарні файли повторно перевірено перед публікацією.

Межі: перевірка remote дітей папки є preflight, не атомарна folder CAS; Dropbox parent_rev застосовується до файлів. Тестовий cloud transport — локальний adapter; живий Dropbox не використовувався для тестових видалень. Перенесення до довільної зовнішньої папки, повний conflict resolver і macOS File Provider залишаються окремими задачами. Автоматичне імпортування recovery не додано.
