# Перевірка 0.14.4

UI: прибрано панель увімкнення/вимкнення нативного провайдера, технічну примітку під кнопкою оновлення та дубль «Підключити Dropbox» у бічній панелі. Вибір порожнього NTFS root автоматично створює native account з усіма папками online-only. Помилки перенесено в загальний banner з назвою акаунта; у footer і tooltip трея показано збережений час останньої успішної синхронізації. Незавершені та невдалі перевірки не змінюють цей час.

Cloud Files: pin intent папок і hydration більше не беруть exclusive oplock; повторне застосування того самого folder pin є no-op. Dehydration, заміна та revert зберігають перевірки ownership/in-sync та захист локальних змін. Тимчасові sharing/oplock errors очікують повтору, а не перетворюються на постійний загальний error. Діагностика зберігає HRESULT/операцію/відносний шлях, без токенів.

Shell: реєструється лише власний sync root; за потреби додається default scope Windows Search для статусів поза user profile, без подолання явних user exclusions. Власна scope rule обліковується в native cache і видаляється при detach; вже наявні правила не видаляються. Per-file volatile transfer state/progress передається за зразком Microsoft CloudMirror; presentation errors не переривають передачу байтів. Стандартні cloud/check glyphs знаходяться поруч з ім'ям або в Status column, а не обов'язково поверх картинки. На реальному drop01/test01/nested01 візуально підтверджено cloud та green check після перечитування Shell registration; початково Explorer відображав застарілий вигляд, хоча provider properties були правильні. drop01 уже був включений у Search scope, тому відсутність індексації не заявляється доведеною причиною саме цього випадку.

Джерела: https://learn.microsoft.com/en-us/windows/win32/api/cfapi/nf-cfapi-cfsetpinstate ; https://learn.microsoft.com/en-us/windows/win32/api/cfapi/nf-cfapi-cfhydrateplaceholder ; https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/CloudMirror/CloudMirror/Utilities.cpp

Перевірено: усі 49 unit/integration tests; source UI smoke UK/EN з реальною local-only rclone sync; автоматичний onboarding/reset із захистом unsent даних; native smoke для hydration/dehydration/pin, busy folder handles і активного/завершеного transfer status; provider CRUD/conflict/reconnect smoke. У Проводнику візуально підтверджено cloud/check/sync glyphs на ізольованому root; на реальному drop01 підтверджено cloud/check. Пройдено також packaged smoke: empty-root onboarding, native hydration/pin/dehydrate, власні subst та захист чужих дисків, tray/minimized/restart, reset/cookies, missing-root logout із recovery, Unicode launcher і layout EXE + app/ + release/. Тестовий async wait виправлено: перевірка очікує фактичного завершення population, а не truthy Promise. Власні регистрации прерваних тестів згорнуто зі збереженням байтів; реальний drop01 не відключався. macOS File Provider ще не реалізовано.
