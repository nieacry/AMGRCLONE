# 0.21.0 — етапи 1–4 одним випуском

Стан: код готовий; автоматичні тести й автотест на Windows пройдено; ручна перевірка нижче ще не виконана. Детально про зміни — `docs/releases/0.21.0.md` і звіти етапів `VERIFICATION-0.17.0.md`, `0.18.0.md`, `0.19.0.md`.

## Уже перевірено автоматично

- `npm test`: 187 тестів, 185 пройдено, 2 пропущено (потребують rclone), 0 помилок. CI на `windows-latest` при кожному push.
- `scripts\verify-stages.cmd` 04.11.2026 на ПК Asiangirls, справжні Windows placeholders і локальна «хмара»: **12 з 12**. Це закриває такі сценарії ручних протоколів:
  - 0.17: видалення папки в Провіднику з підтвердженням, «Видалити в Dropbox», «Повернути папку», «Видалити в мене» з карантином, мале видалення без питань, конфліктна копія на одному ПК, новий файл з уже зайнятим ім’ям;
  - 0.18: видалення в Провіднику під час закріплення (файл 24 МБ із навмисно зупиненим завантаженням);
  - 0.19: новий helper із `inspectMany`, локальні зміни за подіями.

Автотест не бачить справжнього Dropbox і другого комп’ютера. Тому нижче лише те, що залежить від них або від сторонніх програм.

## Підготовка

1. Окремий тестовий обліковий запис Dropbox. Не робочий проєкт.
2. Два ПК (A і B) зі збіркою 0.21.0 з тестовим профілем (`scripts\test-build.cmd`) або з розпакованого ZIP. Той самий тестовий Dropbox на обох.
3. Тестова папка: 40+ дрібних файлів, кілька `.psd`/`.kra`/`.blend`, один файл 500 МБ+.
4. На сайті Dropbox подивитися, скільки днів зберігаються видалені файли (Налаштування → План або сторінка «Видалені файли»). Записати: ___ днів. Від цього залежить, як довго працює «Відновити в Dropbox».

Орієнтовно 60–90 хвилин.

## Ручна перевірка

| # | Сценарій | Очікуваний результат | ✓ |
|---|---|---|---|
| 1 | A і B відкривають один `.psd`; A зберігає; потім B зберігає свою версію | У Dropbox оригінал (версія A) і `… (конфлікт, B, …).psd`; на B оригінал знову хмарний; копія B у карантині | |
| 2 | A і B майже одночасно створюють `test.txt` з різним вмістом | Один `test.txt` + одна конфліктна копія; інші нові файли надіслано без затримки | |
| 3 | На A видалити папку з 30+ файлами → «Видалити в Dropbox» | Папка зникає в Dropbox; на B — банер «У Dropbox видалено елементів»; на B нічого не зникло до рішення | |
| 4 | На B у сценарії 3 → «Відновити в Dropbox» | Файли повертаються в Dropbox (справжнє `files/restore`) і знову з’являються на A | |
| 5 | На A виділити 30 файлів і видалити Shift+Delete | Один банер на всю пачку; у Dropbox і на B нічого не змінилося до рішення | |
| 6 | На B змінити файл; засікти, коли зміна з’явиться на A | До ~10 с | |
| 7 | Photoshop: відкрити `.psd`, змінити, зберегти тричі | Кожне збереження надсилається; без конфліктних копій; на B остання версія | |
| 8 | Krita: те саме з `.kra` | Як у 7 | |
| 9 | Blender: зберегти `.blend` двічі (пише `.blend1` і перейменовує) | Як у 7; `.blend1` теж синхронізується | |
| 10 | Word або Excel: відкрити, змінити, зберегти | Як у 7; тимчасові `~$…` не з’являються в Dropbox | |

| 12 | Почати надсилання файла 500 МБ і вимкнути мережу на 30 с | Надсилання повторюється й завершується (з початку файла — докачування відкладено); без конфлікту | |
| 13 | Сон ноутбука A на 10 хв під час надсилання великого файла | Після пробудження надсилання завершується або повторюється; без конфлікту | |
| 14 | На A закріпити («Завжди на цьому пристрої») папку на кілька ГБ; поки завантажується, видалити й перейменувати файли в іншій папці | Провідник виконує дії одразу, без помилки «Хмарна операція не вдалася» | |
| 15 | Незавантажений файл видалити в Кошик; дочекатися видалення в Dropbox; відновити з Кошика | Записати фактичний результат: відкривається / не відкривається / повертається в Dropbox | |
| 16 | Почати вхід у Dropbox для нового облікового запису й не завершувати його в браузері | Інші облікові записи далі синхронізуються; програма відповідає | |
| 17 | Нічого не змінювати 15 хв; Діагностика → `metrics.cloudListings` | Зростає на 1–2, а не на 12–15 | |

Необов’язково, якщо є час: заповнити тестовий Dropbox до межі й зберегти файл (очікується повідомлення «У Dropbox закінчилося місце», локальна версія ціла); папка на 10 000+ файлів — записати `metrics.lastReconcileMs`.

## Після перевірки

Записати результати в таблицю й закомітити. Випуск: `scripts\release.cmd`. Розгортання: один ПК, через день — решта.
