# 0.16.1 — remote support diagnostics

Windows name validation now carries the exact Dropbox-relative path and a stable reason code: prohibited characters, trailing dots/spaces, or reserved device names. Complete-snapshot case/Unicode normalization collisions carry both original paths. Native error events persist the path and reason in the existing file_events schema, so the Journal no longer substitutes an anonymous account row for these new failures. The error banner translates reason codes into the selected UI language.

Settings provides **Save diagnostics / Зберегти діагностику**, using a native Save dialog. An explicit allowlist exports application/OS versions, account names, provider status and a bounded page of recent failed events. It does not serialize the vault, account configs, OAuth credentials, browser session, file contents, full catalog or raw process logs. The JSON includes English explanations for support. Export runs independently from the sync command queue, works during background enumeration and does not perform cloud operations. Canceling the dialog creates no report. The app never transmits the report.

This release improves diagnosis, not name remapping: no remote/local names are automatically renamed or silently skipped. Existing generic journal rows cannot reveal a path that was not previously captured; the user needs to reproduce the error after updating. Incomplete or invalid snapshots still cannot trigger placeholder reconciliation. Profile format and SQLite schema are unchanged.

Unit tests cover reason/path fields, both collision paths, journal persistence and report privacy/limits. `scripts/diagnostics-smoke.mjs --packaged` covers real provider failure before local changes, retained error history after restart, English/Ukrainian Settings, canceled and successful report saving while background enumeration is stalled, and absence of fixture credentials in the JSON. Tests use a separate workspace profile and fake Dropbox metadata; they do not access a production account.
