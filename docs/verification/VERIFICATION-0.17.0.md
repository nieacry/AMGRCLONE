# 0.17.0 — ніхто не втрачає файли й правки (етап 1)

Стан: код готовий, автоматичні тести проходять; ручна перевірка нижче ще не виконана. Випуск 0.17.0 — після неї.

## Що змінилося

- **Помилки Dropbox.** Відповіді 409 розбираються за `error_summary`. Тимчасові обмеження (`too_many_write_operations`, 429, 5xx, обрив з’єднання) повторюються до 5 разів із паузою; нестача місця й недопустимі імена мають власні повідомлення. Файли, що раніше назавжди застрягли в `conflict`, знову надсилаються, якщо хмарна версія не змінилася.
- **Конфліктні копії.** Якщо правки не можна надіслати, бо в Dropbox інша версія (двоє редагували один файл, двоє створили однакове ім’я, файл видалили в Dropbox під час редагування), локальна версія надсилається поруч як `ім’я (конфлікт, ІМ’Я-ПК, дата час).ext`, а оригінал повертається до хмарної версії. Локальна копія додатково йде в карантин.
- **Масові видалення.** Поріг T = max(20, min(50, 10% каталогу)) за цикл, в обидва боки. Вище порогу — банер у програмі, сповіщення Windows і стан «Потрібна увага» в треї; рішення ухвалює користувач кожного ПК.
- **Карантин.** Повністю завантажений файл копіюється в `<профіль>\quarantine\<обліковий запис>\<дата>\` перед видаленням або заміною placeholder. Якщо копіювання не вдалося, нічого не видаляється. Папки старші за 30 днів видаляються автоматично. Відновлення — скопіювати файл назад у синхронізовану папку.
- **Виправлено:** видалення папки в Провіднику ніколи не доходило до Dropbox (рекурсивний `list_folder` повертає й саму папку, що сприймалося як зміна в хмарі). Файл, видалений і створений знову з тим самим ім’ям, оновлює placeholder замість конфлікту. Нове локальне ім’я, зайняте в Dropbox, більше не зупиняє надсилання всіх інших файлів.

## Автоматичні перевірки

`npm test` — 147 тестів, 145 пройдено, 2 пропущено (потребують встановленого rclone), 0 помилок. Нові набори: `tests/dropbox-errors.test.mjs`, `tests/deletion-guard.test.mjs`, `tests/conflicts.test.mjs`. Для ключових захистів (поріг, карантин, перевірка імені копії, розбір 409) перевірено, що тести падають, якщо захист вимкнути.

## Перед ручною перевіркою

1. Перезібрати helper: `npm run build:native` — у `CloudHost.cpp` додано команду `discard` (видалення власного placeholder після створення конфліктної копії). Без перезбирання конфліктна копія надсилається, але оригінал лишається в стані «конфлікт» з помилкою.
2. Окремий тестовий обліковий запис Dropbox, два ПК (A і B) з цією збіркою, той самий обліковий запис на обох. Не робочий проєкт.
